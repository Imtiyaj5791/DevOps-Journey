# 🔐 IAM Interview Questions - Part 01

---

# Q1. What is IAM?

## Answer

IAM (Identity and Access Management) is an AWS service used to securely manage access to AWS resources.

Using IAM, we can create Users, Groups and Roles, assign permissions through Policies and control who can access which AWS services.

In my project, I mainly work on IAM Users, IAM Roles, Policies and basic access-related activities.

---

# Q2. What is Authentication and Authorization?

## Answer

### Authentication

Authentication means verifying the identity of a user.

Example:

Username and Password

MFA

Access Key

---

### Authorization

Authorization means deciding what actions the authenticated user is allowed to perform.

This is controlled by IAM Policies.

---

# Q3. What is an IAM User?

## Answer

An IAM User is created for an individual person who needs access to AWS resources.

Each user has separate credentials such as:

- Password (Console Access)
- Access Key and Secret Key (CLI/API Access)

Permissions are assigned through IAM Policies.

---

# Q4. What is an IAM Group?

## Answer

An IAM Group is a collection of IAM Users.

Instead of assigning permissions to each user individually, we assign permissions to the Group.

All users in the group inherit the same permissions.

Example:

Linux-Team

Cloud-Team

Developers

---

# Q5. What is an IAM Role?

## Answer

An IAM Role is used to provide temporary permissions to AWS services or users.

Unlike IAM Users, a Role does not have a password or access key.

Example:

An EC2 instance can assume an IAM Role to access an S3 bucket without storing Access Keys on the server.

---

# Q6. What is an IAM Policy?

## Answer

An IAM Policy is a JSON document that defines permissions.

It specifies:

- Which AWS service can be accessed.
- Which action is allowed or denied.
- Which resource can be accessed.

Policies are attached to Users, Groups or Roles.

---

# Q7. What are the different types of IAM Policies?

## Answer

There are three main types.

### AWS Managed Policy

Created and managed by AWS.

Example:

AmazonS3ReadOnlyAccess

---

### Customer Managed Policy

Created and managed by our organization.

Can be attached to multiple Users, Groups or Roles.

---

### Inline Policy

Directly attached to a single User, Group or Role.

It cannot be shared with other identities.

---

# Q8. What is the Root User?

## Answer

The Root User is created automatically when an AWS account is created.

It has full access to all AWS services.

In production, we do not use the Root User for daily activities.

We enable MFA for the Root User and use IAM Users for regular operations.

---

# Q9. What is MFA?

## Answer

MFA stands for Multi-Factor Authentication.

It provides an additional layer of security.

Along with the username and password, the user must also enter a verification code generated by an Authenticator App or Hardware Device.

We always recommend enabling MFA for the Root User and privileged IAM Users.

---

# Q10. What is the Principle of Least Privilege?

## Answer

The Principle of Least Privilege means giving only the minimum permissions required to perform a specific task.

This helps improve security and reduces the risk of accidental or unauthorized access.

# Q12. How do you troubleshoot an "Access Denied" error?

## Answer

First I verify whether the issue is affecting one user or multiple users.

Then I check what action the user is trying to perform.

I verify whether the required IAM Policy is attached.

Then I check whether the user belongs to the correct IAM Group.

If the user is accessing through an IAM Role, I verify that the correct Role is attached.

I also check whether there is any Explicit Deny policy.

If AWS Organizations is used, I verify the Service Control Policy (SCP).

If required, I review CloudTrail logs to identify recent IAM changes.

Finally, after approval, I restore the required permissions, verify user access and update the Jira ticket.

# 🔐 IAM Interview Questions - Part 02 (Advanced)

---

# Q13. What is the difference between IAM User and IAM Role?

## Answer

### IAM User

- Created for an individual person.
- Has permanent credentials like Password or Access Key.
- Used by administrators, developers or support engineers.

### IAM Role

- Does not have permanent credentials.
- Provides temporary permissions.
- Can be assumed by AWS services, users or applications.

In our project, EC2 instances use IAM Roles to access AWS services securely.

---

# Q14. Why do we use IAM Roles instead of Access Keys on EC2?

## Answer

Using Access Keys on an EC2 instance is not recommended because they can be exposed or misused.

Instead, we attach an IAM Role to the EC2 instance.

AWS automatically provides temporary credentials to the instance.

This is more secure and follows AWS best practices.

---

# Q15. EC2 is unable to access the S3 Bucket. What will you do?

## Answer

First I verify whether the EC2 instance has the correct IAM Role attached.

Then I verify whether the IAM Role has the required S3 permissions.

I also verify the S3 Bucket Policy.

If the bucket is encrypted using KMS, I verify the KMS permissions.

Then I test the access from the EC2 instance.

If required, I review CloudTrail logs for Access Denied events.

Finally, after fixing the permissions, I verify that the EC2 instance can access the bucket successfully.

---

# Q16. Yesterday the user was accessing EC2 successfully. Today he is getting "Access Denied". What will you do?

## Answer

First I verify whether the issue is affecting only one user or multiple users.

Then I check what action the user is trying to perform.

I verify whether the required IAM Policy is still attached.

Then I check the IAM Group membership.

I verify whether any Explicit Deny policy has been applied.

If AWS Organizations is used, I verify the Service Control Policy (SCP).

I also review CloudTrail logs to identify any recent IAM changes.

After approval, I restore the required permissions.

Finally, I verify user access and update the Jira ticket.

---

# Q17. What is Assume Role?

## Answer

Assume Role is a process where a user, service or AWS resource temporarily uses another IAM Role.

Instead of using permanent credentials, AWS provides temporary security credentials.

This is commonly used for:

- Cross Account Access
- EC2 accessing AWS services
- Lambda accessing other AWS resources

---

# Q18. What are Temporary Security Credentials?

## Answer

Temporary Security Credentials are short-lived credentials generated by AWS STS.

They include:

- Access Key
- Secret Access Key
- Session Token

These credentials automatically expire after a specific time.

They are more secure than permanent Access Keys.

---

# Q19. What is AWS STS?

## Answer

AWS STS (Security Token Service) is used to generate temporary security credentials.

It is commonly used with IAM Roles and Cross Account Access.

---

# Q20. What is Cross Account Access?

## Answer

Cross Account Access allows users or AWS resources from one AWS account to access resources in another AWS account.

This is achieved using IAM Roles and Trust Policies.

---

# Q21. What is an Explicit Deny?

## Answer

An Explicit Deny always overrides an Allow permission.

Even if a user has an Allow policy attached, access will still be denied if an Explicit Deny exists.

Whenever I troubleshoot Access Denied issues, I always verify whether an Explicit Deny policy is present.

---

# Q22. What is a Service Control Policy (SCP)?

## Answer

SCP is used in AWS Organizations.

It defines the maximum permissions available for AWS accounts.

Even if an IAM User has Allow permissions, the action will fail if it is blocked by an SCP.

---

# Q23. What is an IAM Permission Boundary?

## Answer

A Permission Boundary sets the maximum permissions that an IAM User or Role can receive.

Even if an Allow policy is attached, the user cannot perform actions outside the Permission Boundary.

---

# Q24. What is Access Key Rotation?

## Answer

Access Keys should be rotated regularly for security.

The process is:

- Create a new Access Key.
- Update the application with the new key.
- Verify that everything is working.
- Delete the old Access Key.

This reduces the risk of credential compromise.

---

# Q25. How do you provide temporary access to a user?

## Answer

First I verify the business requirement and obtain approval.

Then I attach the required IAM Policy or assign the appropriate IAM Role.

After the work is completed, I remove the temporary permissions.

Finally, I verify that the user no longer has unnecessary access.

# Q27. What checks do you perform before giving AWS access?

## Answer

Before providing access, I verify:

- User requirement
- Required AWS service
- Least Privilege Principle

- Existing permissions
- IAM Group membership

Only after verification do I assign the required permissions.

# Q28. Explain your IAM troubleshooting approach.

## Answer

Whenever I receive an IAM-related issue, I first identify what the user is trying to access.

Then I verify:

- IAM User
- IAM Group
- IAM Policy
- IAM Role
- Explicit Deny
- SCP (if applicable)
- CloudTrail logs

After identifying the root cause, I restore the required permissions after approval.

Finally, I verify user access and update the Jira ticket.

## Answer

One user reported that he was getting an "Access Denied" error while accessing an EC2 instance.

First I verified the user's IAM permissions.

Then I checked the IAM Group membership.

After receiving approval, I attached the required policy.

The user was able to access the EC2 instance successfully.

Finally, I updated the Jira ticket and documented the root cause.
