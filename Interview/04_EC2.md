# ☁️ EC2 Interview Questions

---

# Q1. What is Amazon EC2?

## Answer

Amazon EC2 (Elastic Compute Cloud) is a virtual server provided by AWS.

It allows us to launch Linux or Windows servers in the cloud within a few minutes.

In my project, we use EC2 instances to host applications.

My responsibilities include monitoring EC2 instances, handling production alerts, extending EBS volumes, troubleshooting issues and coordinating with different teams during incidents.

---

# Q2. What are the components required to launch an EC2 instance?

## Answer

To launch an EC2 instance, we need:

- AMI
- Instance Type
- VPC
- Subnet
- Security Group
- Key Pair
- Storage (EBS)
- IAM Role (if required)

After providing these details, we can launch the EC2 instance.

---

# Q3. What is an AMI?

## Answer

AMI stands for Amazon Machine Image.

It is a template used to launch an EC2 instance.

It contains:

- Operating System
- Required Software
- Configuration
- Application (if customized)

We can use AWS provided AMIs or create our own custom AMI.

---

# Q4. What is the difference between AMI and Snapshot?

## Answer

AMI is used to launch a new EC2 instance.

Snapshot is the backup of an EBS volume.

If I want to create another server with the same configuration, I use an AMI.

If I want to restore only the disk data, I use an EBS Snapshot.

---

# Q5. What is an Instance Type?

## Answer

Instance Type defines the CPU, Memory and Network capacity of an EC2 instance.

AWS provides different instance families based on workload.

For example:

General Purpose - t3, t3a

Compute Optimized - c5

Memory Optimized - r5

Storage Optimized - i3

We select the instance type according to the application requirement.

---

# Q6. What is a Key Pair?

## Answer

A Key Pair is used to securely connect to a Linux EC2 instance using SSH.

It consists of:

- Public Key
- Private Key

AWS stores the public key.

We download and securely store the private key (.pem file).

Without the correct private key, SSH access is not possible.

---

# Q7. How do you connect to an EC2 instance?

## Answer

Normally I connect using SSH.

```bash
ssh -i server.pem ubuntu@<public-ip>
```

If SSH is not working, I verify:

- Security Group
- Port 22
- Public IP
- Route Table
- Internet Gateway
- Correct Username
- Correct PEM Key

If required, I use EC2 Instance Connect or Systems Manager Session Manager.

---

# Q8. What are EC2 Status Checks?

## Answer

EC2 performs two status checks.

### System Status Check

It checks the AWS infrastructure like hardware, power and network.

### Instance Status Check

It checks the operating system running inside the EC2 instance.

Before troubleshooting any production issue, I always verify that both status checks are passing.

---

# Q9. EC2 instance is running but users are unable to access the application. What will you do?

## Answer

First I verify whether the issue is affecting one user or all users.

Then I verify that the EC2 instance is in the Running state.

I check both System Status Check and Instance Status Check.

Then I login to the server using SSH.

I verify the application service.

```bash
systemctl status <service-name>
```

Then I verify whether the application port is listening.

```bash
ss -tulnp
```

Next I check CPU, Memory and Disk utilization.

```bash
top
free -h
df -h
```

Then I review the application logs.

If required, I verify the Security Group, Load Balancer, Target Group Health Check and Route 53.

Finally, I verify the application, monitor CloudWatch dashboard and update the Jira ticket.

---

# Q10. EC2 instance is unreachable. What will you do?

## Answer

First I verify whether the EC2 instance is in the Running state.

Then I check both Status Checks.

Next I verify:

- Security Group
- Network ACL
- Route Table
- Internet Gateway
- Public IP

If SSH is not working, I use EC2 Instance Connect, Systems Manager or EC2 Serial Console if available.

After accessing the server, I check:

```bash
systemctl status sshd
journalctl -u sshd
df -h
```

I also verify CPU, Memory and Network.

Finally, after resolving the issue, I verify connectivity, update Jira and prepare the RCA.

# Q11. Explain one EC2 production issue you handled.

## Answer

One production incident I handled was High Disk Utilization on an EC2 instance.

CloudWatch generated the alert.

First I checked the CloudWatch dashboard to verify whether the utilization was continuously increasing or it was only a temporary spike.

Then I connected to the EC2 instance using SSH.

I checked the filesystem.

```bash
df -h
```

Then I identified the directory consuming maximum space.

```bash
du -sh /var/*
```

The application logs were consuming most of the disk space.

As per our company SOP, I archived the logs and removed old logs that were approved for cleanup.

I also verified logrotate.

Disk utilization was still high, so I increased the EBS volume from the AWS Console.

Then I extended the filesystem.

Finally, I verified the application, monitored CloudWatch, updated Jira and prepared the RCA.

# Q13. What is the difference between Stop, Start, Reboot and Terminate?

## Answer

### Stop

- Instance shuts down safely.
- EBS volume remains attached.
- Public IP changes (unless Elastic IP is attached).
- Private IP remains the same.
- We can start the instance again.

### Start

- Starts a stopped instance.
- Operating System boots normally.
- Instance becomes available again.

### Reboot

- Restarts the operating system.
- Instance remains on the same host in most cases.
- Public IP does not change.
- Used when only OS restart is required.

### Terminate

- Permanently deletes the EC2 instance.
- Root EBS volume is deleted by default.
- Instance cannot be recovered unless backup or AMI exists.

---

# Q14. When will you use Reboot instead of Stop/Start?

## Answer

I use **Reboot** when only the operating system needs to be restarted.

For example:

- Service not responding
- Minor OS issue
- Configuration changes requiring reboot

If the issue is related to underlying hardware or AWS infrastructure, I first verify the EC2 Status Checks before deciding the next action.

# Q15. What is the difference between Instance Store and EBS?

## Answer

| Instance Store | EBS |
|---------------|-----|
| Temporary Storage | Persistent Storage |
| Data lost after instance stop/terminate | Data remains محفوظ |
| Very fast | High durability |
| Cannot create snapshot directly | Snapshot supported |

In production we mainly use **EBS** because data persists even after stopping the instance.

# Q16. What is an Elastic IP?

## Answer

Elastic IP is a static public IP address provided by AWS.

Normally, when an EC2 instance is stopped and started, its public IP changes.

If we associate an Elastic IP, the public IP remains the same.

We generally use Elastic IP for production servers where the public IP should not change.

---

# Q17. What is User Data?

## Answer

User Data is a script that runs automatically when an EC2 instance launches for the first time.

It is commonly used for:

- Installing packages
- Updating the server
- Starting services
- Deploying applications

Example:

```bash
#!/bin/bash
yum update -y
yum install httpd -y
systemctl enable httpd
systemctl start httpd
```

# Q18. What is an ENI (Elastic Network Interface)?

## Answer

ENI is a virtual network card attached to an EC2 instance.

It contains:

- Private IP
- Elastic IP (if attached)
- MAC Address
- Security Group

We can detach an ENI from one instance and attach it to another if required.

# Q19. What are EC2 Purchasing Options?

## Answer

AWS provides multiple purchasing options.

### On-Demand

Pay only for what you use.

Mostly used for development and production.

### Reserved Instance

Lower cost for long-term workloads.

### Spot Instance

Uses unused AWS capacity.

Very low cost but AWS can terminate it anytime.

### Dedicated Host

Physical server dedicated to one customer.

Generally used for compliance or licensing requirements.

# Q20. What is Detailed Monitoring?

## Answer

By default, EC2 sends CloudWatch metrics every **5 minutes**.

If Detailed Monitoring is enabled, metrics are sent every **1 minute**.

It helps detect production issues faster.

---

# Q21. Can you change the EC2 Instance Type?

## Answer

Yes.

Normally we:

- Stop the instance.
- Change the Instance Type.
- Start the instance again.

This is commonly done when CPU or Memory needs to be increased.

Before changing the instance type, we verify application downtime and take the required approvals.

# Q22. What is Hibernate?

## Answer

Hibernate saves the contents of RAM to the EBS root volume before stopping the instance.

When the instance starts again, the applications resume from the previous state.

It is useful when we want to preserve the running session.

---

# Q23. What is EC2 Auto Recovery?

## Answer

EC2 Auto Recovery automatically recovers an instance if AWS detects an underlying hardware failure.

It helps improve availability without manual intervention.

CloudWatch Recovery Alarm is used to trigger this recovery.

# Q27. Difference between Public IP and Elastic IP?

## Answer

### Public IP

- Assigned automatically.
- Changes after Stop and Start.
- Free while the instance is running.

### Elastic IP

- Static IP.
- Does not change after Stop and Start.
- Can be remapped to another instance.
- Used for production workloads.

# Q28. What happens if both EC2 Status Checks fail?

## Answer

First I identify which status check has failed.

If it is a **System Status Check**, I suspect an AWS infrastructure issue.

If it is an **Instance Status Check**, I suspect an operating system issue.

Based on the failure, I troubleshoot the instance or coordinate with AWS Support if required.

# Q30. Explain your complete EC2 troubleshooting approach.

## Answer

Whenever I receive an EC2 alert, I follow a structured approach.

First I check CloudWatch or Grafana to understand when the issue started and whether it is a temporary spike or a continuous issue.

Then I verify the EC2 instance state and Status Checks.

After that, I connect to the instance using SSH.

I check CPU, Memory, Disk, Running Services, Listening Ports and Application Logs.

If infrastructure is healthy, I coordinate with the Application Team.

If AWS configuration needs verification, I check Security Group, Network ACL, Route Table, Load Balancer, Target Group and Route 53.

After resolving the issue, I verify application health, monitor CloudWatch metrics, update the Jira ticket and prepare the RCA.
