# Rolling Update & Rollback

## A Rolling Update allows us to deploy a new application version gradually instead of stopping all existing pods at once, By default, Deployment uses RollingUpdate strategy.
## Rollback means reverting the Deployment to the previous stable version if the new version has an issue.
## maxSurge = how many extra pods can be created temporarily during the update.
## maxUnavailable = how many pods can be temporarily unavailable during the update.

```
Example:

Before:
3 Pods → v1

Update:
v1 → v2

After:
3 Pods → v2

This helps maintain application availability during deployment.

 How Rolling Update Works

Deployment manages the update through ReplicaSets.

Deployment
    ↓
New ReplicaSet
    ↓
New Pods
    ↓
Old ReplicaSet gradually scales down

Example:

Old ReplicaSet → nginx:1.25
New ReplicaSet → nginx:1.27

Kubernetes gradually replaces old pods with new pods.

Update Deployment Image
kubectl set image deployment/roll-dep nginx=nginx:1.27 -n roll-ns

Check Rollout Status
kubectl rollout status deployment/roll-dep -n roll-ns

Watch Rolling Update Live
kubectl get pods -n roll-ns -w

Deployment Revision History
kubectl rollout history deployment/roll-dep -n roll-ns

If the new version has an issue, we can return to the previous working revision.
kubectl rollout undo deployment/roll-dep -n roll-ns
```

# Deployment Strategies: A Deployment Strategy defines how a new version of an application is deployed and how traffic/users are moved from the old version to the new version.

## Recreate:- Recreate stops all Pods running the old version before starting the new version, so it can cause downtime.
## Rolling Update:- Rolling Update gradually replaces old Pods with new Pods without taking all Pods down at the same time.
## Blue/Green:- Blue/Green deployment runs the old and new versions separately and switches traffic to the new version after validation.
## Canary:- Canary deployment gradually exposes the new version to a small percentage of users or traffic before rolling it out to everyone.

## Important:

Kubernetes Deployment natively supports only Recreate and RollingUpdate.
Blue/Green and Canary are deployment patterns implemented using resources such as Deployments, Services, Ingress/controllers, or service mesh.

```
### Recreate Lab:-

apiVersion: apps/v1
kind: Deployment
metadata:
  name: recreate-dep
  namespace: roll-ns

spec:
  replicas: 3

  strategy:
    type: Recreate

  selector:
    matchLabels:
      app: recreate

  template:
    metadata:
      labels:
        app: recreate

    spec:
      containers:
        - name: nginx
          image: nginx:1.25

kubectl apply -f recreate-dep.yml
kubectl get deployment,pods -n roll-ns
kubectl set image deployment/recreate-dep nginx=nginx:1.27 -n roll-ns
kubectl get pods -n roll-ns -w
```
